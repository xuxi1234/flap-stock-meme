# 蝴蝶中秋双系列

嫦娥和玉兔各 7,777 张，0.001 BNB/枚。组合衍生作品：保留 5 幅嫦娥、9 幅玉兔原画，在外围改变装饰。文本为属性组合叙事，不宣称全部独立绘制。

## 重建
在 nft 目录运行 `npm ci --ignore-scripts`、`npm run test:dual`、`npm run build`。
图片在 dual-release/assets，公开构建在 ../dist/editions。图片、故事、组合的唯一性在生成时校验。
官网 GitHub 源码路径为 sites/zhongqiu；生产分支 zhongqiu-dual-7777。

## 合约与交易
MoonCollection 使用 ERC721 和 Chainlink VRF v2.5，无管理员增发或修改价格/元数据的入口。
买家付款预留数量，VRF 返回后按请求顺序结算。随机服务停机时队列等待；不能取消或重抽签。
初始随机费用储备按部署检查时的报价为每套准备 100 次请求，需持续监测余额并补充。结算按钮允许任何钱包调用；本版本没有后台自动结算守护进程。
MoonMarket 使用 EIP712 签名订单，链上公开登记。挂单、撤单和购买有 Gas，平台手续费为零。不托管 NFT。转出后再转回原钱包可能恢复未过期挂单；不想继续出售时必须撤单或取消授权。

## 主网发布
主网部署只允许 GitHub Actions 手动确认，Secret 仅在部署 job 读取。钱包必须匹配授权地址；检查其他共享钱包作业和未确认交易。先保存公开交易参数和哈希，再广播。重复运行恢复原交易，不生成第二套合约。
顺序：部署两套 NFT 和市场、各充值 100 次随机请求的估算费用、各购买 1 枚验证 NFT（总计 0.002 BNB，收入地址不变）、等待 VRF 并结算、核验元数据和源码，全部通过才提交官网的 deployment.json 开放铸造。
源码验证使用 Sourcify v2。任何一步失败会保留检查点，禁止以“已完成”替代实际回执。
NFT 所有权在链上；图片和 JSON 目前由 Vercel 托管，原画和重建代码保存在 GitHub。它们不是全链上图片，也尚未固定到 IPFS。合约固定的 manifest 哈希用于核验作品内容。

## 部署时仍需验证
- Vercel 完整构建中生成的 manifest 必须与本地相同。
- 手机钱包真机连接、签名和主网随机回调需要实际验证。
- 源码核验不等同于第三方安全审计。
