# 蝴蝶 Mint：可选的本机执行方式

**使用 GitHub Actions Secrets 时，请直接阅读 [Actions 中文说明](README.Actions.zh-CN.md)。** 本文仅适用于本机终端入口 `run.mjs`。

这份脚本用于本会话确认的 **Butterfly Mint Check（MINTCHK）小额主网验收项目**。你在自己的电脑运行，检查计划后输入一次私钥，依次完成剩余认购、满额发射、领取。更换不可变收益地址需要部署一套新工厂和项目，地址固定且已完成步骤不会重复，不处理原蝴蝶股票私募，也不自动交易代币、提取金库或测试收益分配。

本机入口的私钥只在本机交互终端输入；GitHub Actions 则使用独立的 Secrets 入口 `actions-run.mjs`。提交此分支或 PR 不会替你签名，不会自动启动脚本，也不代表正式网站已经部署。

## 预算：累计 0.1 BNB，包含 Gas

计费公式：**新旧两个固定钱包分别从 nonce 0 开始，所有已核验成功交易的 BNB 转出金额 + 所有成功及失败交易的实际 Gas + 准备发送交易的 BNB 金额及最大 Gas ≤ 0.1 BNB。**

- 前面已经花费的部署费、创建费、认购及退款 Gas 全部计入；不是每次运行重新给 0.1 BNB。
- 原先 0.01 BNB 已退回，但保守计费不扣除退款，也不扣除后续收到的 BNB；这样不会通过反复退款扩大预算。
- 发射使用项目已经收到的认购款，钱包发射交易的 `value` 为零。已计入的认购款不会重复加一次；发射 Gas 继续计费。
- 单笔最大 Gas 另限 **0.002 BNB**。采用传统 Gas 交易，Gas 数量预留 25%，单价预留 20%；执行前以这两个上限值相乘预留预算，不只是按估算值判断。
- 2026-09-12 只读核验时，已确认累计计费支出 **0.010548475729141262 BNB**，剩余额度 **0.089451524270858738 BNB**。实时结果以每次运行输出为准。
- 这个限制约束本脚本发送的操作，不能阻止你在其他钱包软件另行花钱。运行期间不要用同一钱包同时操作其他项目。发现未知 nonce 后脚本停止，需要补齐交易记录。

## Windows / macOS / Linux 运行步骤

安装 Node.js **22.12 或更高版本**及 Git，在你自己的电脑终端运行。Windows 可以使用 PowerShell。不要在 GitHub Actions、Vercel、Codespaces、远程共享终端或被录屏的终端输入私钥。

```sh
git clone --branch feat/actions-mint-secrets --single-branch https://github.com/xuxi1234/flap-stock-meme.git flap-stock-local
cd flap-stock-local
npm ci --ignore-scripts --prefix scripts/mint-acceptance
npm test --prefix scripts/mint-acceptance
node scripts/mint-acceptance/run.mjs --check
```

`--check` 只读取主网、核验历史和保存本机结果，不需要私钥、不签名。输出固定项目状态及下一步。新工厂尚未部署时应为 `deployFactory`；如果你已通过页面操作，按下面“补齐交易”导入哈希。

确认检查结果后执行：

```sh
node scripts/mint-acceptance/run.mjs --execute
```

1. 核对终端显示的钱包、项目、预算和操作范围。
2. 输入 `EXECUTE 0.1 BNB` 并回车，表示你启动这次固定验收流程。
3. 私钥提示出现后，在**本机终端**输入新确认钱包的私钥；输入不会回显字符。私钥不能作为命令参数、环境变量或文件提供。
4. 脚本依次执行尚缺的部署、创建项目、认购、满额发射、领取，每笔模拟后发送，等待 **12 个区块确认**，核验回执和事件后继续。私钥不需要逐笔重输。
5. 出现“认购 → 发射 → 领取验收完成”后，可把哈希和结果文件发回核验。不要发送私钥。

这不是钱包弹窗流程，`--execute` 会使用你在本机输入的私钥签名。发射会把 0.02 BNB 项目资金用于创建代币及初始购买；发射后不能再按此前的认购退款流程退回。脚本不会替你决定买卖、收益分配或重新发行。

记录保存在你的系统用户目录，和代码分开；同一电脑用户的多个仓库副本共享这一份记录：

- Windows：`C:\Users\你的用户名\.flap-stock-meme\mint-acceptance\journal.json`
- macOS/Linux：`~/.flap-stock-meme/mint-acceptance/journal.json`

记录包含目标、nonce、Gas 上限、哈希、执行结果、事件和累计费用；**不包含私钥或原始签名交易**。不要改写或删除记录来续跑。

断网或关闭终端后，运行原来的 `--check`，再运行 `--execute`。新进程需要重新输入一次私钥。脚本先保存未签名意图，再在本机签名，计算哈希并刷盘保存，最后才广播。网络响应丢失时，按已保存哈希查回执；必要时重签并广播**完全相同的 nonce、参数及哈希**，不自动提高 Gas 或另开 nonce。这无法产生第二笔同 nonce 的成功交易。

如果进程异常退出留下 `runner.lock`，先确认所有脚本进程均已关闭，再只删除该锁文件。**保留 `journal.json`。** 正常退出会自动释放锁。不同电脑不共享锁，请勿同时运行；换电脑前复制结果记录或导入所有缺失哈希。

### 补齐页面操作或其他遗漏交易

如果你已在页面认购/发射/领取，或该钱包做过额外交易，脚本会因为 nonce 不连续而停止。按从早到晚的顺序导入所有缺失哈希（失败交易也要导入，其 Gas 占预算）：

```sh
node scripts/mint-acceptance/run.mjs --check --import-hash 0x完整交易哈希
```

可在同一次命令中重复 `--import-hash`。每笔必须属于新旧两个固定钱包之一的 BSC 主网交易并达到 12 个确认。导入只核验和记账，不重发。如果删除了本机记录，只要钱包已用过后续 nonce，也会停止而不会重新开始一轮预算。

### 失败、卡住或到期

- 回执暂不可读、确认不足或区块重组：等待后 `--check`，不会当作“未发送”自动另发。
- 交易长期 pending：保留记录；不自动加价、不另开 nonce。若你在钱包手动替换，原哈希无法确认时需要人工核对和修复记录，脚本会停止。
- 上一次脚本交易 reverted：Gas 记账后停止。核对原因后，你可以明确执行 `node scripts/mint-acceptance/run.mjs --execute --retry-failed`，重新模拟并在剩余额度内重试；没有无限自动重试。
- 公共 RPC 不稳定：可以把自选 HTTPS RPC 配置为本机 `FLAP_BSC_RPC_URL`，此变量只接受 RPC URL，绝不放私钥。程序不会输出它。
- 项目已取消/到期、出现其他认购者、合约字节码或条款不匹配、预算不足：停止，不自动重新创建项目或提高预算。

JavaScript 无法保证进程内私钥字符串立即清零；请只在可信电脑上运行并在完成后退出进程。脚本不输出 SDK 原始错误/堆栈，避免错误中包含签名请求。本机入口不读取环境变量私钥；Actions 的独立入口仅在用户手动选择 execute 时读取钱包 Secret。
