# 表格名单空投：600 地址，每地址 1 枚

本任务使用用户上传的单列无表头 CSV，第一行也是收款地址。600 个地址全部保留原顺序，不随机生成，不使用文件名中的地址作为代币合约。

- BSC 主网（56）；代币 `0x4b112e1ed0c0cb332d2b39e5dae3bba882f67777`，18 位精度。
- 发送钱包 `0x74a7D3198905C3b4BA53574C2DffEF3aa4e569aA`。
- 免费批量合约 `0x369890cb7a233be14d33fd4265b26afadce00bc0`。没有平台费，调用 value 固定为 0。
- 3 批，每批 200 个地址，每地址 1 枚，合计 600 枚。
- 后一批至少在上一批链上确认时间后 180 秒发送；GitHub 排队、核对记录可能使实际间隔更长。
- 发币只需 3 笔交易。现有授权为 900 枚，启动时会先清零再精确授权剩余数量；授权交易也消耗 Gas。
- 所有历史支出和本次 Gas 仍共用原累计 0.1 BNB 上限。沿用此前已核实的自有钱包本金调拨记账规则，不重置预算。

## 运行

进入 Actions → **蝴蝶表格空投｜3批·每批200地址·每地址1枚**，点击 **Run workflow（运行工作流）**。
分支保持 main；操作选择“执行或继续表格3批”；勾选确认；点击绿色 Run workflow。

已有 Secret `FLAP_MINT_PRIVATE_KEY` 直接复用，必须对应上述 69aA 钱包。可选 `FLAP_BSC_RPC_URL` 作为第一个 HTTPS BSC 节点。私钥只在执行 Job 中读取，不打印、不写文件、不保存签名原文。

“只读检查”不加载钱包私钥，不广播交易。首次执行前先检查链、余额、合约代码、每笔历史收据、累计预算和 nonce；每笔交易会经双节点模拟。

## 中断与结果

新记录使用独立分支 `automation/airdrop-csv600-ledger`。完整交易参数及哈希在广播前持久保存，恢复时先检查原哈希和合约批次完成标记，已完成的地址不重新发送。三个成功批次后停止，重跑同一工作流不会生成另一套任务。

每个执行步骤上传 `plan.csv`、`results.csv`、`journal.json` 和 `summary.txt`。只有回执中200条到账事件均为1枚，才记作该批发放完成。失败交易消耗的 Gas 也计入预算；失败后停止。

原72轮运行已在 GitHub 取消。其已完成27轮和历史交易原样保存在 `data/csv600-prior72.json`，每次仍重新查链计费。新任务要求原运行维持取消、原检查点不出现新增交易。不要同时重启旧72轮；本次会占用钱包后续nonce。若以后要恢复旧任务，需先合并本次交易记录并重新核对累计预算，不能直接使用旧执行参数。
