# 蝴蝶股票真实批量发币

入口 `https://gupiao.sh/?view=airdrop`。用户钱包签名后执行 BSC 主网交易。旧预览已升级为实际交易流程。

## 使用步骤

1. 连接持有代币和 BNB 的钱包，确认在 BSC 主网。
2. 读取代币合约信息，选择指定地址、私募配比或随机地址。私募固定 151 个 0.2 BNB 名额、360 个 0.05 BNB 名额，权重 4:1，共 964 份。
3. 生成清单；私募发币必须提供两档完整实际地址。重复或无效行会阻止生成。跨档同地址保留两档权益，锁定发送时合并数量。
4. 在“真实链上发放”核对 Gas 预算（默认每任务 0.02 BNB，含部署、授权、发送），锁定清单，下载任务备份。
5. 点击“检查下一步与网络费”。首次使用会准备部署工具交易；已有匹配的工具则复用。检查代币余额不足时不会先请求部署。
6. 核对本步操作及手续费，勾选确认，在钱包中签名。依次完成部署、授权和批次发放。每笔发币交易最多 200 个地址，每一步由用户主动确认。
7. 下载真实记录 CSV。记录含哈希、实际到账和 Gas。若有未消耗授权，最后一步提供清零。

## 合约与执行约束

`contracts/src/ButterflyDistributor.sol`：无 owner、无管理后门、无工具费、无需把代币先转入工具。仅从调用者本人通过 transferFrom 直接发给接收人。零地址、发送者自己、工具自身不能作为接收地址。新版合约单批最多 200 条，前端固定每批 200 条；200 × 7 枚只生成一笔发币交易，合计 1,400 枚。首次部署与 ERC-20 授权仍是独立交易。

- 合约将调用者与批次 ID 的完成状态存储在链上，拒绝同一批次重放；任何转账失败均整批回滚。
- 同一名单标准化、同一钱包和代币生成固定任务与批次 ID，名单双向重排不改变任务。不同的任务不是同一个发放授权，请用户核对部分重叠名单。
- 每步前核对 BSC 链、当前钱包、工具完整运行时代码、代币精度、余额、授权和最高手续费。
- 授权仅针对剩余数量；已有不同额度先清零。Gas 预算按累计实际网络费加下一笔 gasLimit × gasPrice 保守预留，不将退款抵扣。
- 记录已发送量与实际到账差异；转账税可能减少接收人到账。支持符合 ERC-20 常用行为的代币，并非任意自定义代币都兼容；实际交易前 estimateGas 会模拟并在 revert 时阻止签名。
- 随机地址是真实地址格式，但没有已确认接收人，不代表真实用户。发送后可能无人控制且无法收回。

## 恢复

任务、每笔钱包请求意图和哈希保存在当前浏览器本地，不上传后台。浏览器多标签页使用互斥锁。发送意图先落盘，再请求钱包；只有显式拒签会清除意图。请求超时不会自动重发。

刷新后连接原钱包会恢复任务。跨设备需要导入任务备份；请不要清除浏览器数据或同时在不同设备操作同一钱包。上次请求未返回哈希时，从钱包活动记录找到哈希填入恢复框。恢复时核对 from/to/data/value/nonce、三次确认和批次到账事件。历史回执及 Gas 重新核对。未取得一致证据时停止。

- `npm run build`
- `npx vitest run src/airdrop/math.test.ts src/airdrop/live.test.ts`

已完成本地合约和客户端恢复测试；尚未替用户部署主网工具或转账。首次主网部署与小额到账验收需要用户在页面签名，不能把代码构建通过等同于主网验收完成。

## 旧任务切换单笔 200 地址

旧版任务仍按 25 地址恢复，旧部署运行时代码仍受精确校验。连接原钱包，点击「核对已发记录，合并剩余地址」。支持未发送及部分已发送任务。升级前自动核对有哈希的待确认交易；逐笔验证历史回执，并核对旧工具全部批次完成标记。只接受从第 1 批开始连续、无遗漏的已发记录；记录不一致就停止。保留完整名单、历史交易哈希、累计 Gas 和原预算，保存升级前备份。新工具需要重新部署一次；旧工具如有授权，先撤销后再部署、授权新版。不同版本的工具缓存与批次标识隔离。

用户此前部署的旧工具 `0xcc05a7d3e526de13febee2e3ad4a797ed26e512d` 无升级权限，因此不能直接修改已部署代码。页面升级不自动发送交易，仍由用户逐步核对签名。

部分发放的任务保留原始完整名单，将旧版已成功批次标记为 legacy，并记录已发地址数。新批次从未发地址开始，批次 ID 包含跳过数量，旧版记录不会计入新版批次进度。例如已发 25/200，则新交易为剩余 175 × 7 = 1,225 枚；待确认的第二批若成功，自动改为剩余 150 × 7 = 1,050 枚。历史费用完整累加。每次准备新交易前，重新检查旧工具是否有额外发放，防止另一设备继续旧任务后重复发币。
