## 部署与发布

1. `node contracts/nft/scripts/launch-reserved.mjs` 只读检查接收地址、网络、余额、随机服务和公开素材。
2. 在 GitHub 工作流“蝴蝶股票NFT｜四张指定分配”选择“部署并分配四张”，填写 `APPROVE_RESERVED_MAX_0.002_BNB`，由用户最终启动。
3. 保留工作流产物 `journal.json` 和 `frontend-disabled.json`。若失败，按日志、交易 nonce 和回执核对；不得删除部署标记或直接重跑。
4. 同一提交运行 `verify-reserved-live.mjs` 独立核对三份运行时代码、五笔回执、四次初始 Transfer、当前所有权、合约绑定、经济参数和费用。
5. 核验通过后，将前端配置中的 `enabled` 改为 true，写入 `src/nft/deployment.json`，同步发布官网和独立 NFT 站。
6. 检查四张指定编号的持仓、公开规则、铸造弹窗、主网合约链接与移动端显示。新合集配置含 `preallocatedSupply: 4` 和接收地址，前端据此显示相应规则，并从链上验证这两个参数。

旧版配置已从前端代码移除。发布前不得用旧合约地址冒充新合集，也不得提前宣称四张 NFT 已到账。
